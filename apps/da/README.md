# DataInsight / DA Indicator

DataInsight is the DA indicator service. It is a Spring Boot backend for
indicator metadata, dimensional query planning, SQL generation, dashboards,
authorization, monitoring, and AI/DataGPT-related endpoints.

In the local GraphBuilder integration, DA consumes the business KG generated by
GraphBuilder and uses it to build SQL for Ad-Hoc indicator queries.

## Main Features

- Indicator, dimension, hierarchy, datasource, dashboard, and workspace metadata APIs.
- SQL generation for measures, dimensions, filters, drill paths, derived dimensions, and complex measures.
- Dynamic datasource support for MySQL-compatible query engines.
- Local business KG loading through `indicator.graph.data-path`.
- Monitoring, decision tree, dimension analysis, and AI-related service modules.

## Requirements

- JDK 8 or a compatible JDK for this Spring Boot 2.5.x project.
- Maven 3.6 or newer.
- MySQL 5.7/8.0-compatible database for the DA metadata schema.
- Optional: Redis on `127.0.0.1:6379` for features that use Redis.
- Optional for GraphBuilder integration: a generated business KG file at
  `GraphBuilder/output/business_kg/indicator-data.ttl`.

The repository contains several environment-specific YAML files. Treat them as
development references only. Do not paste real secrets into LLM tools and do not
commit local password changes.

## Install And Build

```bash
cd /path/to/DataInsight
mvn -DskipTests package
```

The runnable jar is generated at:

```text
target/da-indicator-0.0.1-SNAPSHOT.jar
```

## Prepare Local MySQL

Create an empty DA metadata database and load the schema:

```bash
mysql -u YOUR_DB_USER -p -e \
  "CREATE DATABASE IF NOT EXISTS indbtest DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"

mysql -u YOUR_DB_USER -p indbtest < schema.sql
```

The schema gives the service the required tables. Business data and metadata may
still be empty until imported or created through APIs.

## Run Locally

Prefer command-line overrides for local credentials instead of editing committed
YAML files:

```bash
cd /path/to/DataInsight
mvn spring-boot:run \
  -Dspring-boot.run.profiles=dev \
  -Dspring-boot.run.arguments="\
--spring.datasource.dynamic.datasource.mysql.url=jdbc:mysql://127.0.0.1:3306/indbtest?allowMultiQueries=true&useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&autoReconnect=true&failOverReadOnly=false&maxReconnects=30&initialTimeout=2&connectTimeout=3000 \
--spring.datasource.dynamic.datasource.mysql.username=YOUR_DB_USER \
--spring.datasource.dynamic.datasource.mysql.password=YOUR_DB_PASSWORD \
--indicator.graph.data-path=/path/to/GraphBuilder/output/business_kg/indicator-data.ttl"
```

Or run the packaged jar:

```bash
java -jar target/da-indicator-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=dev \
  --spring.datasource.dynamic.datasource.mysql.url="jdbc:mysql://127.0.0.1:3306/indbtest?allowMultiQueries=true&useUnicode=true&characterEncoding=utf-8&serverTimezone=Asia/Shanghai&autoReconnect=true&failOverReadOnly=false&maxReconnects=30&initialTimeout=2&connectTimeout=3000" \
  --spring.datasource.dynamic.datasource.mysql.username=YOUR_DB_USER \
  --spring.datasource.dynamic.datasource.mysql.password=YOUR_DB_PASSWORD \
  --indicator.graph.data-path=/path/to/GraphBuilder/output/business_kg/indicator-data.ttl
```

Default local port:

```text
http://localhost:8091/
```

## GraphBuilder Integration

1. Start or run GraphBuilder and generate:

   ```text
   /path/to/GraphBuilder/output/business_kg/indicator-data.ttl
   ```

2. Start DA with:

   ```text
   --indicator.graph.data-path=/path/to/GraphBuilder/output/business_kg/indicator-data.ttl
   ```

3. Use DA query APIs or the GraphBuilder UI paths that call DA-compatible
   Ad-Hoc semantics.

## Run Tests

Compile and package without tests:

```bash
mvn -DskipTests package
```

Run the full test suite:

```bash
mvn test
```

Some tests may require local fixtures or database access. For SQL builder-only
changes, run the relevant `BuildSqlService*Test` classes when available.

## Can A Fresh Clone Start?

A fresh clone can compile with Maven. A full local service start also needs a
local MySQL database initialized from `schema.sql`, local database credentials
provided at runtime, and preferably a GraphBuilder-generated business KG file.
Without those runtime dependencies, the application may build successfully but
will not be fully usable.
