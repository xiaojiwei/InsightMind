# 可复现 HR 演示初始化设计

**日期：** 2026-09-02
**状态：** 已确认方案，待实施

## 目标

让任何人从仓库最新代码下载后，在本地完成构建和初始化，即可看到并使用两个 HR 演示看板：

- `dash_hr_human_capital_panorama`（人力资本经营驾驶舱｜组织人才全景）
- `dash_hr_talent_vitality_pulse`（组织效能驾驶舱｜人才活力脉搏）

演示环境必须同时具备且激活以下内容：

- MySQL HR 演示数据库 `HRRDB`
- 数据图谱 `kg_20260901_003.ttl`
- 业务图谱 `indicator-data.ttl`
- 两张 HR 看板和它们引用的 Ad-Hoc 查询配置

所有演示数据均为仓库内生成的确定性合成数据，不依赖本机遗留数据库、外部导出文件或真实业务数据。

## 约束

- 不引入新的服务、子系统或运行时依赖。
- 不提交真实账号、密码、LLM 密钥或任何真实业务数据。
- 保留现有 Java 常用依赖；本次不重新引入已移除的下钻专用依赖。
- 初始化脚本只操作其明确声明的演示数据库和演示输出目录，不触碰用户的其他库或配置。
- `apps/ad/config.local.yaml` 保持本地忽略文件；初始化不得覆盖已有本地配置。

## 方案

### 1. 确定性 HR 数据库种子

新增可复用的 HR 演示数据生成器，创建并填充 `HRRDB` 所需的标准 HR 表：

- `regions`、`countries`、`locations`
- `departments`、`jobs`
- `employees`、`job_history`

数据生成器使用固定种子生成 107 名合成员工、部门、岗位、地域和员工异动记录。数据需覆盖人员规模、任职年限、薪酬、组织层级、岗位族群、地域、历史异动等两个看板的指标和维度。

现有 `apps/ad/hr_analytics_views.sql` 在该库上创建以下演示视图：

- `vw_hr_employee_profile`
- `vw_hr_department_profile`
- `vw_hr_career_mobility`

数据库名称、主机、端口、用户名和密码通过现有 MySQL 环境变量覆盖；默认值仅用于本地演示。脚本会在开始时检查 MySQL 可用性和数据库名格式，失败时明确退出。

### 2. 统一初始化脚本

调整 `scripts/init-demo-db.sh`，使其只初始化 HR 演示需要的数据库资产：

1. 创建或重建指定的 HR 演示库。
2. 运行 HR 合成数据生成器。
3. 应用 HR 分析视图。
4. 保留 DA 所需的本地指标元数据库初始化。
5. 移除 TPCDS、`da_tms`、CELN 和通话质检数据的初始化调用。

数据库重建行为会在脚本帮助和日志中明确说明。脚本只删除目标演示库，不会清理其他数据库。

### 3. 激活图谱和看板资产

修复 `scripts/init-demo-assets.sh`，从 `demo/default/ad/output` 正确恢复当前 HR 演示资产到 `apps/ad/output`：

- 数据图谱 `kg_20260901_003.ttl`
- 业务图谱 `business_kg/indicator-data.ttl`
- 两个 HR 看板定义
- 它们需要的 Ad-Hoc 查询配置

脚本不再调用针对旧通话质检表的图谱清理逻辑，也不再输出 TPCDS 名称。恢复完成后会解析两个 TTL，并校验只有两张演示看板及其所需配置被安装。

显式执行的演示资产恢复可以替换演示输出目录中的旧演示资产；服务启动时的自动补种仅在业务图谱缺失时补齐，不主动删除用户已有资产。

### 4. 默认配置和服务启动

将仓库默认演示数据源从 TPCDS 对齐到 `HRRDB`，使 AD 在无旧本地配置的情况下连接初始化后的 HR 演示库。

`scripts/insightmind.sh` 继续将 DA 指向 AD 输出目录中的 `business_kg/indicator-data.ttl`。DA 通过现有 `GraphStore` 加载业务图谱；AD 通过现有输出目录加载数据图谱和看板定义，不增加新的加载器。

如发现已有 `apps/ad/config.local.yaml` 与 HR 演示库不一致，初始化过程不得静默覆盖它，而是给出需要调整的明确提示。

### 5. 文档与运行指引

更新根目录 README、AD README 和 `demo/default/README.md`：

- 默认演示明确为 HR 演示，而不是旧 TPCDS 或通话质检演示。
- 给出从新克隆到可访问两张看板的最短命令序列。
- 明确环境变量覆盖方式、数据库重建范围和验收 URL。
- 说明图谱可由 HR 数据源重新构建；两张随仓库交付的演示看板不依赖 LLM 在线调用才能首次显示。

## 验证

### 自动化检查

- 解析两个 Turtle 文件，确认可读且包含三元组。
- 断言演示资产中仅包含两个 HR 看板，并且引用的 Ad-Hoc 配置完整。
- 校验资产初始化脚本不再包含旧 TPCDS、通话质检表或错误的双重 `output/output` 路径。
- 校验 HR 数据生成器对固定输入生成稳定的表、视图依赖和行数。
- 对修改的 Shell 脚本运行语法检查。

### 干净环境验收

在没有历史 `apps/ad/output`、没有旧 TPCDS/通话质检演示数据的环境中：

1. 构建 AD 与 DA。
2. 执行 HR 数据库初始化和演示资产恢复。
3. 启动 AD、DA。
4. 验证 AD 的数据图谱、业务图谱均可加载。
5. 在首页仅看到两张 HR 看板。
6. 打开两张看板，并验证指标卡、指标单元格和图表的明细钻取、业务解释、维度下钻均返回有效结果。

集成验证会使用独立的临时演示数据库名，避免影响开发者本地的默认 HR 演示库。

## 非目标

- 不迁移或保留旧通话质检、CELN、TPCDS 演示看板。
- 不为演示系统新增云服务、容器编排或外部数据依赖。
- 不改变现有图谱本体、指标语义或 DA 的图谱查询架构，除非验证发现 HR 演示资产与其存在明确不兼容。
