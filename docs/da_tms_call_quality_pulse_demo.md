# 通话质量脉搏：从看状态到追踪结果的 BI 产品演示方案

## 1. Demo 定位

### 产品名称

**门店通话质量脉搏（Call Quality Pulse）**

### 一句话价值

帮助店长和区域运营负责人在每天的电话运营中完成一条闭环：

> 看状态 → 找异常 → 解释原因 → 下钻证据 → 执行动作 → 追踪结果

它不是一张静态质检报表，而是一套面向管理者的质量运营系统：上层给出业务结论，中层解释异常来源，底层提供逐通证据，最后把问题转成辅导任务并验证改善效果。

### 目标用户

| 用户 | 主要任务 | 首要问题 |
| --- | --- | --- |
| 店长 | 每日管理门店质量 | 今天是否需要介入？该辅导谁？ |
| 区域运营 | 横向比较门店、发现共性问题 | 哪些门店/问题类型正在恶化？ |
| 质检主管 | 复核规则和证据 | 低分是否有充分 ASR 证据？ |
| 专家/销售 | 查看自己的改进项 | 我哪一个 SOP 环节没有做好？ |

### 管理视角与分析视角

产品分为两个入口：

- **运营驾驶舱**：默认给店长使用，只展示结论、异常、优先级和行动清单。
- **分析工作台**：给质检主管和区域运营使用，支持切维度、看关系、查逐通记录、验证口径。

## 2. 演示故事线

演示不要从“这是一个图表”开始，而要从一个真实管理问题开始：

> 杭州演示体验中心今天的平均质量分仍然接近目标，但邀约结果开始下降。店长需要判断：是整体能力下滑，还是某几个专家在某个 SOP 环节出现了问题？问题有没有证据？应该给谁安排什么辅导？辅导后是否真的改善？

### 推荐 12 分钟演示流程

| 时间 | 操作 | 观众得到的结论 |
| ---: | --- | --- |
| 0:00–1:00 | 进入门店质量驾驶舱 | 今日质量状态为“建议关注” |
| 1:00–2:30 | 查看趋势、目标线、环比 | 问题不是总量，而是质量/邀约转化出现偏离 |
| 2:30–4:00 | 点击问题来源排行 | 主要异常集中在“需求确认”和“下一步动作” |
| 4:00–5:30 | 查看 SOP 旅程健康度 | 其他环节正常，两个环节形成主要损失 |
| 5:30–7:30 | 点击专家辅导矩阵 | 张三样本量足且持续低覆盖，应优先辅导 |
| 7:30–9:00 | 下钻到逐通电话 | 用 ASR、规则命中和时间点证明问题 |
| 9:00–10:30 | 创建辅导行动 | 指定负责人、改进目标和截止时间 |
| 10:30–12:00 | 查看行动追踪 | 后续质量分和环节命中率改善，可关闭行动 |

## 3. 页面设计

## 3.1 首页：门店质量驾驶舱

### 顶部筛选栏

- 日期：今日、近 7 日、近 30 日、自定义。
- 门店：默认当前门店，可切换到区域/全部门店。
- 专家：全部专家或指定专家。
- 通话类型：全部、已接通、邀约、回访、试驾跟进。
- 数据状态：显示数据截止时间和最近刷新时间。

筛选应全局联动，点击任意图表后保留筛选上下文，并在页面顶部展示“当前分析条件”。

### 第一屏布局

```text
┌────────────────────────────────────────────────────────────┐
│ 门店质量驾驶舱  [日期] [门店] [专家] [通话类型]   数据截至… │
├────────────────────────────────────────────────────────────┤
│ 总通话  有效接通率  SOP命中率  问题率  平均质量分  邀约成功率 │
├────────────────────────────────────────────────────────────┤
│ 今日结论：建议关注                                       │
│ 质量分较昨日 -4.8，主要由“需求确认”和“下一步动作”拖累。     │
│ 建议优先辅导：张三；建议复盘：18 通低覆盖电话。              │
├───────────────────────────┬────────────────────────────────┤
│ 质量趋势与目标线           │ 问题来源排行                   │
│ 近7日质量/覆盖/邀约趋势     │ 低覆盖、动作缺失、需求确认…     │
├───────────────────────────┼────────────────────────────────┤
│ SOP旅程健康度              │ 专家辅导矩阵                   │
│ 环节命中率、环比变化        │ 样本量 × 质量 × 变化趋势        │
├────────────────────────────────────────────────────────────┤
│ 行动清单：优先级 / 负责人 / 改进项 / 截止时间 / 当前状态     │
└────────────────────────────────────────────────────────────┘
```

### 核心 KPI 卡

每张卡同时展示当前值、目标值、环比和状态，不只展示一个大数字。

| 指标 | 示例展示 | 状态逻辑 |
| --- | --- | --- |
| 总通话数 | 1,284 / 目标 1,200 | 达标/未达标 |
| 有效接通率 | 72.4% / 环比 +2.1pp | 过程健康度 |
| SOP 命中率 | 68.7% / 目标 75% | 质量健康度 |
| 问题率 | 21.3% / 环比 +5.4pp | 越低越好 |
| 平均质量分 | 64.2 / 目标 70 | 质量状态 |
| 邀约成功率 | 18.6% / 环比 -3.2pp | 结果状态 |

### 今日结论卡

结论卡是首页的核心，不由用户自行拼图。建议根据规则生成三种状态：

- **运行平稳**：核心指标均达标，且没有连续两日恶化。
- **建议关注**：存在一项核心指标偏离目标，或出现中等异常。
- **需要介入**：质量分、问题率或结果指标达到严重阈值，且存在明确责任对象。

结论内容按“结论 + 影响 + 主要原因 + 建议动作”生成，例如：

> **建议关注**：今日平均质量分 64.2，较近 7 日均值下降 4.8 分；主要原因是需求确认命中率下降 12.4pp，集中在张三的 18 通有效样本中。建议今天完成一次“需求确认 + 下一步动作”专项辅导，并复盘其中 5 通低覆盖通话。

## 3.2 分析工作台：质量诊断

从首页任一异常点击“查看原因”进入。页面采用左侧条件、中央关系分析、右侧异常摘要的结构。

### 诊断链路

```text
指标异常
  ↓
问题类型 / SOP环节
  ↓
门店 / 专家 / 客户意图 / 日期
  ↓
逐通电话
  ↓
ASR证据、质检规则、客户结果
```

### 三个分析区

1. **异常概览**：异常指标、偏离幅度、影响样本量、首次出现时间。
2. **关系分析**：问题类型 × SOP 环节 × 专家 × 客户意图的联动交叉分析。
3. **证据列表**：逐通电话、质量分、缺失槽位、下一步动作、邀约结果和复盘状态。

### 推荐图表

- 质量分与邀约成功率散点图：识别“分数低且影响结果”的专家。
- 专家 × SOP 环节热力图：发现特定专家的特定能力短板。
- 问题类型 Pareto 图：按影响通话数排序，突出累计 80% 问题来源。
- 趋势对比图：当前周期、上周期、目标线三线对比。
- 客户意图分组图：比较不同客户场景下的 SOP 命中和转化结果。

## 3.3 专家辅导页

这是管理动作的承接页，不只是排名。

### 专家卡片

每位专家展示：

- 有效通话数，避免小样本误判。
- 平均质量分、SOP 命中率、邀约成功率。
- 环比变化和近 7 日趋势。
- 最弱 SOP 环节。
- 待复盘通话数、进行中行动数。

### 辅导优先级

建议使用一个可解释的优先级分：

```text
辅导优先级 = 问题率偏离目标 × 样本可信度 × 结果影响系数 × 连续恶化系数
```

页面必须同时展示构成因素，避免出现无法解释的“AI 排名”。小于 10 通有效样本的专家标记为“样本不足”，不直接进入高优先级队列。

## 3.4 逐通工作台：ASR 与质检证据

点击一条异常记录进入通话详情。

### 左侧：通话摘要

- 专家、门店、客户匿名 ID、通话时间、时长。
- 接通状态、邀约结果、质量分、SOP 等级。
- 缺失槽位和命中的 SOP 环节。

### 中部：对话时间轴

- 专家/客户角色区分。
- 关键质检证据高亮。
- 每条证据显示时间点，如 `01:24`。
- 点击证据可定位到对应 ASR 文本。

### 右侧：规则与建议

| 区块 | 内容 |
| --- | --- |
| 已命中 | 已覆盖的小达成点及原文证据 |
| 未命中 | 缺失的沟通动作 |
| 影响判断 | 对质量分、邀约结果的可能影响 |
| 辅导建议 | 可直接复制给专家的改进话术 |
| 管理动作 | 创建复盘、加入案例库、标记误判 |

证据显示必须区分三类：**原始 ASR**、**规则判断**、**业务推断**。业务推断不可伪装成原始事实。

## 3.5 行动中心：从问题到闭环

行动中心承载“执行动作”和“追踪结果”。

### 行动字段

| 字段 | 说明 |
| --- | --- |
| 行动标题 | 例如“张三｜需求确认专项辅导” |
| 来源异常 | 关联指标、问题类型、SOP 环节 |
| 负责人 | 店长、质检主管或专家本人 |
| 改进目标 | 例如需求确认命中率从 52% 提升到 70% |
| 证据范围 | 关联的逐通电话或样本集合 |
| 截止时间 | 支持逾期标记 |
| 状态 | 待处理、进行中、待验证、已完成、已关闭 |
| 验证窗口 | 例如行动后 7 日 |

### 行动状态流转

```text
发现异常 → 已分派 → 辅导进行中 → 待验证 → 达标关闭
                         ↘ 未改善 → 延长辅导 / 升级处理
```

关闭行动时，系统自动展示行动前后对比：质量分、问题率、目标 SOP 命中率、邀约成功率和有效样本量。

## 4. 指标与数据口径

### 指标分层

| 层级 | 指标 | 口径 |
| --- | --- | --- |
| 规模 | 总通话数 | 选定时间和筛选条件下的通话记录数 |
| 接通 | 有效接通率 | 有效接通通话数 / 总通话数 |
| 质量 | 平均质量分 | 有质检结果通话的质量分平均值 |
| 质量 | 问题率 | 命中任一问题规则的通话数 / 有质检通话数 |
| SOP | 环节命中率 | 已命中检查点数 / 应检查点数 |
| 覆盖 | 关键信息覆盖率 | 已命中关键槽位数 / 应覆盖槽位数 |
| 结果 | 邀约成功率 | 邀约成功通话数 / 有效接通且具备邀约场景通话数 |
| 改善 | 环比变化 | 当前周期值 - 上一等长周期值；比例指标以百分点展示 |

### 口径提示

页面底部固定显示：

> 数据源：`da_tms` 通话与质检数据；质检口径：最新一版规则结果；当前筛选数据截至：YYYY-MM-DD HH:mm；小于 10 通有效样本的分组仅作参考。

指标详情支持“查看口径”：分子、分母、过滤条件、更新时间、数据负责人和版本号。这样可以让 Demo 具备商业 BI 产品的可信度。

## 5. 异常解释设计

### 异常检测

第一版 Demo 采用可解释规则，后续再增加统计异常：

- 低于目标：当前值 < 目标值。
- 环比恶化：当前值较上周期下降超过阈值。
- 连续恶化：连续 3 个周期下降。
- 结构异常：整体正常，但某个专家/意图/门店显著偏离整体。
- 样本异常：分母过小，标记为“不可下结论”。

### 解释模板

每个异常固定输出五项：

1. **发生了什么**：指标当前值和目标差异。
2. **影响多大**：影响通话数、专家数、潜在结果数。
3. **主要来源**：问题类型、SOP、专家、客户意图。
4. **证据是什么**：具体通话和 ASR 片段。
5. **建议做什么**：行动类型、负责人、目标和截止时间。

示例：

> 问题率由 15.9% 升至 21.3%，增加 5.4pp，涉及 18 通有效通话。问题主要集中在“需求确认”缺失，其中张三贡献 11 通；典型证据是专家直接介绍产品，未确认预算、使用场景和购车时间。建议安排专项辅导，验证目标为 7 日内该环节命中率提升至 70%。

## 7. Demo 数据建议

建议保留现有演示窗口，使用一个能够讲出“先正常、后恶化、再改善”的数据故事：

| 阶段 | 数据表现 | 页面效果 |
| --- | --- | --- |
| 近 7 日基线 | 质量分约 68–72，SOP 命中率稳定 | 趋势基线和目标线 |
| 当前日 | 质量分下降，问题率上升 | 首页进入“建议关注” |
| 异常分组 | 张三在需求确认、下一步动作明显偏低 | 热力图和优先级 |
| 证据样本 | ASR 中缺失预算/场景确认，下一步动作为空 | 逐通证据 |
| 行动后窗口 | 质量分和目标环节命中率回升 | 行动前后对比和关闭 |

如果暂时没有真实行动后的数据，可以在 Demo 数据集中增加“行动前/行动后”标记，并明确标注为演示模拟数据，不将模拟结果与真实质检结果混在一起。

## 8. 技术实现建议

### 第一阶段：可演示闭环

1. 将现有单一 `executive_report` 看板拆成首页多个组件。
2. 为所有组件补充全局筛选、点击联动和 drill path。
3. 增加目标值、环比、状态标签和结论卡。
4. 复用现有 `call_quality_workspace` 生成逐通详情和 SOP 证据。
5. 新增轻量行动数据结构：JSON 或本地表均可，用于 Demo 持久化状态。
6. 增加行动前后 7 日验证查询。

### 第二阶段：产品化增强

- 统一异常中心，支持预警确认、忽略和升级。
- 支持规则版本、指标版本和质检版本。
- 支持自然语言提问，例如“为什么本周邀约成功率下降？”
- 增加语义层解释：问题指标与来源字段、事实表、过滤条件可追溯。
- 增加嵌入式专家工作台，允许专家直接查看自己的改进任务。

### 推荐 API 能力

```text
GET  /api/call-quality/overview
GET  /api/call-quality/trend
GET  /api/call-quality/issues
GET  /api/call-quality/sop-health
GET  /api/call-quality/experts
GET  /api/call-quality/calls/{callId}
GET  /api/call-quality/actions
POST /api/call-quality/actions
PATCH /api/call-quality/actions/{actionId}
GET  /api/call-quality/actions/{actionId}/verification
```

所有响应建议包含 `dataAsOf`、`metricVersion`、`sampleSize` 和 `filters`，方便前端展示可信度信息。

## 9. 验收标准

### 业务验收

- 店长在 30 秒内能回答“今天是否需要介入”。
- 点击异常后，3 次以内能定位到问题专家和 SOP 环节。
- 每个重要异常都能查看至少一条逐通证据。
- 从异常记录创建行动不超过 1 分钟。
- 行动详情可以看到目标、负责人、截止时间和验证结果。
- 所有核心指标都能查看分子、分母、时间范围和更新时间。

### 交互验收

- 首页筛选能同步影响 KPI、趋势、排行、热力图和行动清单。
- 点击图表不会丢失原有筛选条件。
- 从首页进入明细后可以返回，并恢复原来的分析上下文。
- 小样本分组有清晰提示，不制造虚假排名。
- ASR 证据、规则结果和业务推断使用不同视觉标识。

### 演示验收

- 能完整跑通“状态—异常—原因—证据—行动—结果”六步。
- 不依赖现场临时修改数据库或手工拼接页面。
- 数据异常、接口失败或无证据时有可理解的空态提示。

## 10. 最终 Demo 讲解词

> 我们先看门店今天的质量状态，而不是先看明细。系统判断当前为“建议关注”：总通话量达标，但平均质量分和邀约成功率出现背离。
>
> 点击异常，我们看到问题主要集中在需求确认和下一步动作两个 SOP 环节。再切到专家矩阵，张三的样本量足够，而且连续几天在这两个环节偏低，因此不是偶然的小样本波动。
>
> 继续下钻到逐通电话，系统把质检规则、缺失槽位和 ASR 原文对齐到具体时间点。这里可以看到专家介绍产品后直接结束，没有完成预算、场景和下一步动作确认。
>
