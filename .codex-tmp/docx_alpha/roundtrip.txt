## 一、九天 AlphaData 产品简介

九天 AlphaData 是基于 Agentic AI 技术架构构建的数据智能平台。致力于实现数据要素的“存、管、用”全链路智能化，功能覆盖从数据集成、数据运营、数据消费到敏捷分析的数据全生命周期。

产品通过“自然语言交互”重构数据使用范式，支持各省专公司通过标准化 API 接口（接口规范）进行调用，支持将智能问数、分析、可视化等能力快速集成至第三方业务系统，赋能业务快速数智化。

### 1.1、数据问答

提供基于自然语言的数据查询服务。系统通过语义解析引擎，将用户的业务问题自动转化为标准的 SQL 查询指令。支持配置行业术语词典，能够精准识别业务意图，并直接从数据库中检索事实数据，返回精准的统计结果或明细列表。

功能特性

- 多表关联查询：支持跨库、跨主题域的数据检索。系统能自动识别数据实体间的关系，自动处理多张数据表之间的 Join（连接）逻辑，满足综合分析需求。
- 多数据库支持：支持 MySQL、ClickHouse、PG、OB 等十余类数据库。
- 自定义业务知识：支持自定义业务知识，在生成 SQL 中将参考预置的知识，提升准确性。
- 多轮上下文交互：具备会话记忆能力。支持基于上一次的查询结果进行追问、筛选或下钻（例如：先问“总收入”，再接着问“其中排名前十的省份”），无需重复输入条件。
- 复杂逻辑解析：支持识别包含多重限制条件、聚合计算及对比分析的指令。能够准确处理同环比计算、复合筛选（如“ARPU值大于50且活跃天数大于7天”）等复杂业务逻辑。
- 意图推理与拆解：思考模式下，针对模糊或复杂的业务问题，系统会自动进行任务反思、深度思考，提高查询成功率。
- 执行过程可视：规划模式下，支持查询过程的透明化展示。通过分步推理机制，将一个大问题转化为多个可执行的查询步骤，逐步显示 SQL 生成逻辑与执行步骤，方便业务人员核对数据口径，确保结果可追溯、可信赖。
- 自主数据分析：自主分析模式下，支持模拟人类 DBA 思维逻辑的操作方式，通过多步 ReACT 进行数据探索和分析。

### 1.2、数据可视化

旨在实现从“数据”到“视觉呈现”的自动化流转。基于大语言模型（LLM）的语义理解能力，能够精准解析用户的自然语言查询指令，自动适配最佳图表模型，并输出准确、美观的 ECharts 配置或成品图表。

有效降低了复杂图表的配置门槛，支持业务人员通过对话方式进行探索式数据分析，实现数据洞察的即时可视化。

### 1.3、智能表格助手

智能表格助手是面向复杂数据场景的对话式智能分析助手，基于多智能体协同技术，实现对表格数据的全流程处理、关联分析与智能决策支撑。支持多数据表联合问答分析，可兼容含合并单元格、多工作表等复杂结构的 Excel 文件，有效降低专业数据分析的技术门槛，赋能业务人员高效完成数据治理与价值挖掘。

功能特点：

- 复杂表格兼容处理：具备复杂结构解析能力，全面支持合并单元格、跨 Sheet 页引用、嵌套公式关联等非常规表格场景，无需人工预处理即可实现精准数据识别与结构化解析。
- 自动化数据建模：支持基于业务场景的异常值检测、时序趋势预测、多维度相关性分析，自动生成可验证的分析模型与结论，支撑数据驱动决策。
- 多格式批量协同：支持 xlsx、csv、word、markdown 等多格式文件的批量接入与解析，实现跨文件、跨格式的数据关联比对与综合分析。
- 多智能体深度分析：基于智能体协作架构，对复杂分析任务进行分层拆解与任务调度，实现多维度、深层次的逻辑推演，保障分析结果的准确性与专业性。

## 二、智能问数前序准备工作

九天 AlphaData 作为 “Data+AI” 深度融合的产品，其价值实现高度依赖数据质量、业务对齐等基础条件，与单纯的 AI 工具类产品存在本质差异——前者以“数据驱动分析、分析支撑决策”为核心，数据是底层基石，技术环境是落地保障，业务需求是方向指引。若前序准备工作缺失或不到位，后续即便完成产品交付，也可能出现“分析结果偏差大”、“功能与业务脱节”、“系统运行不稳定”等问题，导致产品无法发挥实际价值。因此，应用方需重点完成以下几类前序准备工作，为后续交付落地奠定基础。

### 2.1、数据语义优化

具体如何配置数据语义，请参考原文档对应章节。

1. 业务化模型配置：
   - 字段优化：将数据库中晦涩的字段名（如“cust_id”“fee_amt”）改为业务易懂的名称（“客户 ID”“月均消费金额”），避免大模型理解偏差；
   - 维度成员枚举：通过数据字典将编码值转换为业务语言（如“套餐类型 1/2”映射为“5G 畅享套餐 / 4G 融合套餐”）；
   - 字段类型校准：将非标准类型字段（如存储为字符串的日期）转换为标准类型，确保大模型可识别“近 3 个月”“环比”等时间维度查询。
2. 冗余字段屏蔽：隐藏对分析无用的技术字段（如“数据加载时间”“接口调用 ID”），减少大模型识别干扰，提升问答响应速度。

### 2.2、业务知识对齐

1. 业务知识映射配置：
   - 指标口径定义：梳理核心业务指标（如“用户渗透率”“营销转化率”），明确计算逻辑、统计维度及例外场景；
   - 业务黑话映射：建立日常表述与标准字段的对应关系，确保精准识别业务习惯用语。
2. 高频场景语料准备：
   - 典型问答整理：收集 20–30 条业务高频问题及标准答案，作为训练语料；
   - 场景规则配置：针对核心场景设置关联逻辑，提升分析精准度。
3. 试错迭代优化：
   - 首轮测试验证：组织业务人员试用，收集“问答不符”案例；
   - 快速调整优化：基于测试反馈更新知识映射与语料库，确保适配业务实际需求。

## 三、数据源的配置与管理

AlphaData 2.0 数据源的配置均全部通过前台页面进行配置管理，如需申请前台应用账号请联系相关团队。

目前已支持的数据类型：

- MySQL
- PostgreSQL
- OceanBase
- ClickHouse
- Oracal
- Excel、CSV
- Sqlite
- Schema-Excel（仅适用于离线配置）

正在开发中的数据库类型：

- 磐维数据库
- Doris
- GBase
- WuTongDB（河南公司需求）

### 3.1、连接数据源

- 进入前台页面“数据云盘”。
- 点击“新建数据源”，进入数据源配置界面。
- 选择数据库类型，并填写对应的配置参数。由于后台需要获取元数据与枚举值信息，并通过大模型对数据源进行自动分析与学习，通常连接过程预计需要 30 秒至 10 分钟左右。
- [图片]

### 3.2、数据源质量评估

数据源的质量与后续数据问答质量密切相关。在连接数据源后，点击“我的数据源”，找到已配置的数据源，“质量评估”中会给出该数据源存在的质量问题及改进建议。

- [图片]

### 3.3、数据源编辑

在 AlphaData 上进行编辑不会对连接的数据库产生任何影响。任何对数据源的变更不会影响原有数据，仅被用于后续数据问答。

点击已配置的数据源，点击右侧抽屉弹窗的“数据源信息”→“数据源编辑”。

#### 3.3.1、手动编辑数据源

你可以手动填写字段的别名、注释、备注信息。

- 别名：字段的中文名，用于直观标识字段含义；
- 注释：字段的业务解释，说明该字段的具体用途、逻辑规则；
- 备注：补充说明字段的特殊规则、关联关系等。

填写完之后，需点击右下角“提交所有变更”才能生效。

#### 3.3.2、导出线下编辑

- 点击“导出数据源”，下载该数据源的元数据信息表。
- 打开 Excel 数据表进行编辑，但不要变动“列 ID”“表 ID”，否则会导致上传失败。
- 编辑完成后，点击数据源编辑页面右下角的“导入数据源”。

#### 3.3.3、智能优化数据源

提供 AI 辅助优化数据元信息功能。勾选需要优化的列信息，点击右上角“批量 AI 优化”，即可批量完成数据源信息的补充及优化。优化内容包括数据表标签、描述，数据列别名、注释、备注、主外键信息、是否时间字段等。也可手动调整 AI 优化后的内容。

完成 AI 自动优化后，同样需要点击右下角“提交所有变更”生效。

### 3.4、知识库的创建及管理

#### 3.4.1、管理知识库

点击“数据云盘”→“知识库管理”，可查看当前账号下配置的所有知识库信息。可新建知识库，或对已有知识库进行管理，并根据知识类别创建多个知识库。

#### 3.4.2、创建知识

- 进入“知识库”模块后，通过右上角“新建知识”按钮添加知识条目；同时支持对已有知识条目进行删除、编辑操作。
- 新建知识时，需填写“标题”（知识标识）与“内容”（知识详情）。
- “是否必要”开启时，该知识会被数据问答强制调用，并以系统级提示词形式传递给大模型；关闭时，知识条目将根据数据问答的语义需求动态触发调用。

### 3.5、知识库挂载至数据源

完成知识库创建与知识配置后，可将一个或多个知识库挂载到指定数据源。挂载后，该数据源进行数据问答时会自动调用这些知识库作为专属知识来源，确保 AI 回答更贴合业务场景、精准一致。

### 3.6、数据源操作审计

系统会自动记录当前数据源的所有操作行为，包括操作用户身份、执行时间及具体操作内容，实现数据源全流程可审计、可追溯。

### 3.7、数据源权限配置

原文称该功能暂未完成前端开发，预计 2026 年 1 月上线。功能上线后，支持将数据源权限精准赋权给指定用户/用户组，同时可实现行级别的数据权限精细化控制。

## 四、九天 AlphaData 接入形式

2026 年 2 月起，所有调用均需订购中台能力。

### 4.1、产品化交付

省专用户登录办公网后可直接在九天 AlphaData 产品页面内使用 AI 数据问答、数据可视化、自动报告生成等核心能力，无需各省专公司提供算力资源。用户完成账号注册与数据配置后，即可开展数据智能问答、分析等操作，实现“开箱即用”。

适用场景：适用于业务需求标准化、无特殊定制化要求的单位。

时间计划：

- 目前需联系 AlphaData 团队开通系统账号权限，约 1–3 个工作日。
- 公网试用环境正在推进中，原文预计 3 月上线。

### 4.2、能力化交付

通过 API、MCP 服务等形式，向各省专公司输出 AlphaData 的核心能力模块，支持与现有业务系统进行接口对接，实现能力嵌入与流程融合。

适用场景：适用于需将 Data+AI 能力融入现有业务流程，提升整体业务系统智能化水平的省专公司。

交付流程：

- 需求确认：明确需接入的能力模块及对接系统参数。
- 接口开发：AlphaData 团队根据对接需求完成 API 接口开发与调试。
- 联调测试：协助应用单位完成能力模块与现有系统的联调测试。

时间计划：

- 各能力 API 接口均已具备，后续持续更新功能 API。
- 仅需开通网络策略即可访问，时间约 1–3 个工作日。

#### 4.2.1、API 接口方式

支持 AlphaData 核心能力模块与各省现有业务系统对接，各省通过 API 接口调用各类 AlphaData 能力。详见《新 AlphaData 2.0 产品对接技术说明》。

#### 4.2.2、私有化镜像部署

AlphaData 2.0 版本暂不支持私有化部署。如需私有化部署，仅提供 AlphaData 1.0 产品。

针对“本省数据敏感、无法出库”的特殊场景，提供本地部署方案，确保数据全程在本地内部流转。

资源需求：

- 算力资源：由各省自行提供 GPU 算力及大模型 API，兼容 OpenAI 接口且模型参数规模不小于 72B；
- 服务器配置：推荐 CPU ≥ 16 核、内存 ≥ 64GB、硬盘 ≥ 2TB，操作系统 Linux CentOS 7.6 及以上，Python > 3.10。

#### 4.2.3、聚智智能体平台

支持在一级聚智智能体平台上通过插件方式调用，适用于应用方本地建设智能体应用，将 AlphaData 的数据问答、数据可视化等能力作为工具调用。原文同时注明 2026 年 2 月暂不提供聚智平台接入。

### 4.3、定制化交付

面向各省专公司特有业务场景，提供“需求调研—方案设计—产品开发—部署交付”全流程定制化服务。

适用场景：适用于业务模式差异化显著、有高价值专属场景的单位。

交付流程：

- 需求调研：明确定制化目标与核心指标。
- 方案设计：制定技术方案，经确认后启动开发。
- 开发测试：完成产品开发、功能实现与测试。

时间计划：根据开发团队排期及需求难度而定，约 2 个月至半年不等，原文称已排期至 2026 年下半年。

### 4.4、联合开发交付

面向有较强技术研发能力的内部单位，提供 AlphaData 部分产品源代码及开发文档，支持各省专单位基于源码进行二次开发。目前已有广东、北京等省份加入协作开发机制。
